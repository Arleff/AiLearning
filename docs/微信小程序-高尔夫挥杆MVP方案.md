# 微信小程序：高尔夫挥杆分析 MVP 方案

## 1. 目标

做一个可以尽快上线验证付费意愿的微信小程序 MVP，满足以下最小闭环：

1. 用户上传一段高尔夫挥杆视频。
2. 系统自动识别挥杆主体与球杆头部轨迹。
3. 生成带轨迹叠加的视频或关键帧截图。
4. 用户通过订阅或单次付费解锁完整分析结果。
5. 用户可以在小程序内查看历史分析记录。

这个 MVP 的核心不是做“专业级动作诊断系统”，而是先验证两个问题：

- 用户是否愿意为“自动挥杆轨迹分析”付费。
- 哪种收费模式更容易转化：订阅制还是按次付费。

---

## 2. MVP 功能边界

### 2.1 必做功能

#### 用户侧

- 微信授权登录
- 上传本地挥杆视频
- 查看上传进度与分析状态
- 查看分析结果
  - 原视频
  - 轨迹叠加视频或关键帧图
  - 简单文字结论
- 购买解锁
  - 单次付费解锁当前报告
  - 订阅会员查看全部报告
- 历史记录列表

#### 系统侧

- 视频存储
- 视频转码与抽帧
- 挥杆轨迹检测
- 异步任务处理
- 订单与会员状态管理
- 基础运营后台
  - 用户列表
  - 分析记录列表
  - 订单列表
  - 手动退款/补单备注

### 2.2 明确不做

为了保证 MVP 足够快，不建议首版做下面这些能力：

- 3D 姿态重建
- 实时挥杆指导
- 多机位融合
- 教练点评社区
- 复杂动作评分体系
- AI 对话陪练
- 多运动项目扩展

## 3. 推荐的 MVP 产品形态

### 3.1 用户流程

最短闭环建议如下：

1. 用户进入小程序首页。
2. 看到产品价值说明与示例效果。
3. 上传一段正面或侧面挥杆视频。
4. 系统提示“正在分析，预计 10-30 秒”。
5. 返回一个预览版结果：
   - 低清预览图
   - 简要提示，例如“已识别挥杆轨迹”
6. 用户选择：
   - 单次付费：解锁本次完整结果
   - 开通会员：解锁当前及会员期内的全部结果
7. 支付成功后查看：
   - 带轨迹的视频
   - 关键帧截图
   - 简单文本报告
8. 历史页可再次查看已购结果。

### 3.2 首版结果页建议

首版不要追求“专业术语很多”，而是追求“效果明显、容易理解”：

- 挥杆轨迹线
- 上杆/下杆/击球瞬间关键帧
- 球杆头路径示意
- 一个简单结论卡片，例如：
  - 上杆轨迹偏内
  - 下杆过陡
  - 击球区路径较稳定

这样更容易让用户感知价值，也能降低算法解释成本。

## 4. 技术方案建议

当前仓库不是小程序业务项目，更像学习资料仓库。因此如果要真正落地，建议采用以下结构：

```text
apps/
  mini-golf/              # 微信小程序前端
services/
  api/                    # 业务 API、支付、用户、订单
  analysis-worker/        # 视频处理与轨迹分析
ops/
  docker/                 # 部署配置
docs/
  微信小程序-高尔夫挥杆MVP方案.md
```

### 4.1 前端：微信小程序

推荐优先级：

1. **原生微信小程序**
2. Taro
3. uni-app

如果目标是“最快上线”，建议直接使用 **原生微信小程序**：

- 文件上传和支付链路最直接
- 调用微信登录、订阅消息、支付能力更顺手
- 不需要为跨端做额外适配

前端页面建议：

- 首页
- 上传页
- 结果页
- 订单/会员页
- 我的/历史记录页

### 4.2 后端：FastAPI

推荐使用 **Python + FastAPI**：

- 适合快速做 API
- 容易接 OpenCV、MediaPipe、YOLO 等视觉工具链
- 对异步任务和后台服务支持较轻量

建议的核心模块：

- `auth`：微信登录态、用户信息
- `upload`：上传签名、回调
- `analysis`：任务创建、状态查询、结果返回
- `billing`：订单、会员、权益校验
- `admin`：后台查询接口

### 4.3 视频分析：先用“够用”的算法路线

MVP 不建议一开始做复杂自研模型，优先用成熟组件拼出结果。

推荐的技术路线：

1. **视频预处理**
   - `ffmpeg` 统一转码
   - 降帧到 30fps 或更低
   - 固定分辨率，例如 720p

2. **人体姿态识别**
   - `MediaPipe Pose` 先做人关键点识别
   - 目标：识别肩、肘、腕、髋等关键点

3. **球杆/杆头轨迹识别**
   - MVP 建议两种方案二选一：

#### 方案 A：半规则方案，最快落地

- 假设用户上传的是固定机位、背景相对干净的视频
- 通过人体手腕关键点附近区域，结合边缘检测/光流追踪寻找杆头轨迹
- 适合先验证产品，成本低

优点：

- 开发快
- 不需要立刻标注大量数据

缺点：

- 对拍摄环境要求较高
- 稳定性一般

#### 方案 B：轻量检测模型，效果更稳

- 训练一个轻量目标检测模型识别球杆头或球杆线段
- 可以用 YOLOv8n/YOLO11n 这类轻模型
- 再结合关键点与时序平滑输出轨迹

优点：

- 准确率上限更高
- 更适合后续演进

缺点：

- 需要小规模标注数据
- 首版准备成本更高

**MVP 建议先从方案 A 开始**，只要能在规范拍摄条件下稳定输出轨迹，就足以验证付费。

### 4.4 存储与任务架构

建议采用异步处理，避免小程序请求超时。

#### 基础架构

- 对象存储：腾讯云 COS 或阿里云 OSS
- 数据库：MySQL
- 缓存：Redis
- 队列：Redis Queue / Celery / Dramatiq
- 回调：任务完成后写入结果表

#### 任务流

1. 小程序请求上传凭证
2. 前端直传视频到对象存储
3. 前端调用创建分析任务接口
4. 后端写入任务表并投递队列
5. Worker 下载视频并分析
6. 输出：
   - 轨迹叠加视频
   - 关键帧图
   - 简要结论 JSON
7. 用户轮询任务状态或接收订阅消息提醒

## 6. 收费方案设计

MVP 需要同时支持 **订阅制** 和 **单次付费**，但展示策略要简单。

### 6.1 建议的收费组合

#### 方案 1：单次付费

- 例如：`9.9` 或 `19.9` 元 / 次
- 适合首次体验用户
- 解锁当前这一次完整分析结果

#### 方案 2：周卡或月卡订阅

- 例如：
  - 周卡 `29.9`
  - 月卡 `69.9`
- 会员期内不限次数或限制次数

### 6.2 MVP 推荐策略

首页默认突出：

- “先试一次”：单次付费
- “经常练球更划算”：会员订阅

推荐的权益逻辑：

- 未付费：只能看缩略预览
- 单次付费：解锁当前报告
- 会员：解锁会员期内全部报告

### 6.3 支付实现建议

微信小程序内建议使用：

- **微信支付下单**
- 后端处理支付回调
- 支付成功后立即更新权益

注意点：

- 会员是“周期权益”，后端必须以服务端状态为准
- 首版先不要做复杂自动续费
- 如需“订阅”体验，可先做“手动购买月卡”，本质仍然是一次性支付换固定周期权益

这样能显著降低首版支付复杂度。

## 7. MVP 算法输出定义

为了控制范围，首版只输出这些内容：

### 7.1 可视化输出

- 原视频上叠加球杆头轨迹
- 3-5 张关键帧图
  - 站位
  - 上杆顶点
  - 下杆
  - 击球瞬间
  - 收杆

### 7.2 结构化输出 JSON

```json
{
  "swing_type": "side_view",
  "tempo_score": 72,
  "path_summary": "downswing_outside_in",
  "checkpoints": [
    {"name": "backswing_top", "timestamp_ms": 840},
    {"name": "impact", "timestamp_ms": 1360}
  ],
  "insights": [
    "上杆轨迹较稳定",
    "下杆路径略陡",
    "击球区轨迹可继续优化"
  ]
}
```

### 7.3 不建议首版输出

- 绝对专业评分
- 明确医疗/运动损伤建议
- 夸张的“AI 教练级诊断”

首版结论应该偏保守，避免误导。

## 9. 最快落地路径

如果目标是“尽快上线而不是一步到位”，建议按下面顺序实现。

### 阶段 1：先打通最小闭环

- 小程序上传视频
- 后端存储视频
- Worker 输出简单轨迹视频
- 结果页展示
- 单次付费解锁

这一步就已经可以开始验证有没有人愿意付费。

### 阶段 2：补会员体系

- 月卡/周卡权益
- 历史记录
- 权益校验
- 订单页

### 阶段 3：提升分析效果

- 更稳定的杆头识别
- 更好的关键帧检测
- 更清晰的文本建议
- 对不同拍摄角度做兼容

## 10. 风险与规避

### 10.1 最大风险：算法不稳定

MVP 最大风险不是支付，而是上传不同环境的视频后，轨迹识别失败。

规避方式：

- 首页明确拍摄规范
  - 固定机位
  - 单人出镜
  - 光线充足
  - 侧面或正后方标准角度
- 首版只支持 1-2 种标准视角
- 失败任务给出退款或重试券

### 10.2 小程序审核风险

避免使用过度夸张的医疗、训练效果承诺，例如：

- “保证提升成绩”
- “专业教练完全替代”

应改为：

- “提供挥杆轨迹可视化与动作参考”

### 10.3 成本风险

视频分析计算比普通图文应用成本高，建议：

- 先限制视频时长，例如 5-10 秒
- 限制分辨率
- 限制单用户每日免费次数

## 11. 建议的首版 KPI

MVP 阶段建议盯以下指标：

- 上传完成率
- 分析成功率
- 结果页打开率
- 单次付费转化率
- 会员购买率
- 复购率
- 单条视频平均处理成本

如果只能盯 3 个指标，优先看：

1. 分析成功率
2. 单次付费转化率
3. 单条视频毛利

---

## 12. 推荐结论

如果要快速做出一个能收费的版本，我的建议是：

1. **前端用原生微信小程序**
2. **后端用 FastAPI**
3. **分析服务先走 MediaPipe + OpenCV + 规则方法**
4. **支付先做单次付费，再补月卡会员**
5. **只支持标准拍摄场景**
6. **先验证“能不能稳定画出轨迹并有人付费”**

最重要的是先把“上传 -> 分析 -> 可视化 -> 支付解锁”跑通，而不是一开始就追求高精度动作诊断。
